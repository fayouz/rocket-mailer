## Pré-remplir le message

Passez un brouillon à `mount({ draft })` pour le premier affichage, ou à `setDraft()` ensuite. Seuls les champs fournis sont modifiés.

```js
const mailer = RocketMailer.mount('#mailer', {
  // …
  draft: {
    from: 'Agence Lyon <lyon@crm.exemple.com>',
    to: ['client@exemple.com'],
    subject: 'Votre devis n°42',
  },
})

// Plus tard, quand l'utilisateur ouvre une autre fiche :
mailer.setDraft({ to: ['autre.client@exemple.com'], subject: 'Votre commande' })
```

### Champs du brouillon

::field-group
  :::field{name="from" type="string"}
  Adresse d'expédition à présélectionner, ex. `"Agence Lyon <lyon@crm.exemple.com>"`. Elle peut être une des adresses proposées à l'utilisateur, ou une adresse que **votre application** est autorisée à imposer (voir [Déclarer l'application](/embed/application#adresses-dexpédition)). Elle est ajoutée à la liste « De » si besoin. Une adresse non autorisée est refusée à l'envoi.
  :::

  :::field{name="to" type="string[]"}
  Destinataires. Les adresses invalides sont ignorées.
  :::

  :::field{name="cc" type="string[]"}
  Copie. Le champ est affiché automatiquement s'il n'est pas vide.
  :::

  :::field{name="bcc" type="string[]"}
  Copie cachée.
  :::

  :::field{name="subject" type="string"}
  Objet (255 caractères maximum).
  :::

  :::field{name="htmlBody" type="string"}
  Contenu HTML du message, chargé dans l'éditeur. Pratique pour proposer un texte déjà personnalisé par votre application.
  :::

  :::field{name="mailbox" type="string"}
  Identifiant d'une [boîte d'envoi](/administration/mailboxes) rattachée à votre application : l'email part par son serveur et sa copie est rangée dans ses « Envoyés ». Remplace `from`.
  :::

  :::field{name="template" type="string"}
  Identifiant (ou IRI) d'un template. Sans `htmlBody`, le composeur **charge le template** (contenu et objet par défaut) et remplit ses variables avec `variables`. Avec `htmlBody`, il sert seulement à attribuer l'envoi au template.
  :::

  :::field{name="variables" type="object"}
  Valeurs des [variables du template](#variables-de-template), à plat (`{ "client.prenom": "Claire" }`) ou imbriquées (`{ client: { prenom: "Claire" } }`). Elles s'appliquent au template chargé, et au contenu déjà présent.
  :::

  :::field{name="attachments" type="string[]"}
  Identifiants de pièces jointes déjà envoyées **au nom de cet utilisateur** par votre backend (voir [Joindre un document de votre application](#joindre-un-document-de-votre-application)). Elles s'ajoutent aux pièces jointes déjà présentes, et l'utilisateur peut les retirer.
  :::
::

::note
L'utilisateur garde la main : un brouillon ne fait que remplir le formulaire, rien n'est envoyé sans son clic sur **Envoyer**. Pour envoyer sans interaction, utilisez l'[API](/api/emails).
::

::tip
`setDraft()` n'est pris en compte qu'une fois le composeur prêt. Appelez-le dans `onReady` ou après, ou passez le brouillon initial via l'option `draft`.
::

## Variables de template

Un template peut contenir des variables, comme `{{ client.prenom }}` ou `{{ devis.numero }}` (voir [Templates](/administration/templates#variables)). Votre application connaît ces valeurs : passez-les avec le template, le composeur fait le remplacement.

```js [crm.js]
mailer.setDraft({
  to: ['claire@client.example'],
  template: '0199a1b2-…',   // id du template « Relance devis »
  variables: {
    client: { prenom: 'Claire', societe: 'Société Exemple' },
    devis: { numero: '42', montant: '1 250 €' },
  },
})
```

- Les valeurs sont insérées **comme du texte** : un `<` reste un `<`, jamais du HTML.
- Une variable sans valeur prend sa **valeur par défaut** si le template en définit une.
- Les autres sont listées dans un encadré **Variables à compléter** : l'utilisateur les saisit, et l'envoi est bloqué tant qu'il en reste.

::tip
L'identifiant d'un template figure dans son URL (`/templates/<id>`) et dans `GET /api/email_templates`, que votre backend peut appeler au nom de l'utilisateur pour retrouver un template par son nom.
::

## Pièces jointes

L'utilisateur joint ses fichiers directement dans le composeur, avec le bouton **Joindre des fichiers** ou par glisser-déposer. Il peut joindre jusqu'à 10 fichiers, de 10 Mo chacun et 25 Mo au total par défaut. Il n'y a rien à faire de votre côté.

### Joindre un document de votre application

Votre application peut aussi joindre un document qu'elle produit, comme un devis PDF ou une facture :

1. votre **backend** envoie le fichier à Rocket Mailer **au nom de l'utilisateur**, avec le secret de l'application et `X-Impersonate-User` ;
2. il transmet l'`id` renvoyé à votre page ;
3. la page le passe au composeur avec `setDraft({ attachments: [id] })`.

::code-group
```ts [serveur.ts]
app.post('/devis/:id/rocket-mailer-attachment', requireLogin, async (req, res) => {
  const pdf = await generateQuotePdf(req.params.id) // Buffer

  const form = new FormData()
  form.append('file', new Blob([pdf], { type: 'application/pdf' }), `devis-${req.params.id}.pdf`)

  const response = await fetch(`${API}/api/attachments`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${APP_TOKEN}`,
      'X-Impersonate-User': req.user.email, // le même utilisateur que le composeur
      'Accept': 'application/json',
    },
    body: form,
  })
  res.status(response.status).json(await response.json()) // { id, filename, mimeType, size }
})
```

```js [page.js]
document.querySelector('#envoyer-devis').addEventListener('click', async () => {
  const attachment = await fetch('/devis/42/rocket-mailer-attachment', { method: 'POST' }).then(r => r.json())
  mailer.setDraft({
    to: ['client@exemple.com'],
    subject: 'Votre devis n°42',
    attachments: [attachment.id],
  })
})
```
::

::note
Une pièce jointe appartient à l'utilisateur au nom duquel elle a été envoyée. Le composeur n'accepte que les pièces jointes de **son** utilisateur, et chacune ne peut partir qu'avec **un seul** email. Les fichiers téléversés mais jamais envoyés sont supprimés par la [tâche de purge](/getting-started/installation#tâches-planifiées).
::

## Événements

### `onReady()`

Le composeur est authentifié, affiché et prêt à recevoir un brouillon.

### `onSent(email)`

Appelé après chaque envoi réussi. L'objet reçu :

```ts
interface SentEmail {
  id: string // identifiant de l'email dans Rocket Mailer
  subject: string
  to: string[]
  status: 'queued' | 'sent' | 'failed'
}
```

Le statut est en général `queued` : l'envoi SMTP est fait juste après par le worker. Pour suivre le statut final, appelez `GET /api/emails/{id}` depuis votre backend (voir [API](/api/emails)).

```js
RocketMailer.mount('#mailer', {
  // …
  onSent: async (email) => {
    // Tracer l'échange sur la fiche client de votre application
    await fetch(`/clients/42/activities`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ type: 'email', rocketMailerId: email.id, subject: email.subject }),
    })
  },
})
```

### `onError(error)`

`getToken()` a échoué, par exemple parce que votre backend a répondu une erreur ou que l'utilisateur n'existe pas dans Rocket Mailer. Affichez un message dans votre page : sans jeton, le composeur affiche « Composeur indisponible » au bout de 15 secondes.

```js
RocketMailer.mount('#mailer', {
  // …
  onError: () => {
    document.querySelector('#mailer-error').textContent =
      'Votre compte n’est pas encore activé dans Rocket Mailer. Contactez votre administrateur.'
  },
})
```

## Renouvellement du jeton

Le jeton d'embed vit 15 minutes. Quand l'API le refuse parce qu'il a expiré, l'iframe demande un nouveau jeton à la page, `embed.js` rappelle `getToken()`, puis la requête est rejouée **une fois**. L'utilisateur ne perd ni son brouillon ni sa saisie. Vous n'avez rien à faire, sinon garder `getToken()` fonctionnel tant que la page est ouverte : si la session de votre application expire, `getToken()` échouera et `onError` sera appelée.
