::tip
Ouvrez la console du navigateur sur la page qui embarque le composeur : la plupart des problèmes y laissent un message explicite (CSP, `postMessage`, réponses HTTP).
::

## L'iframe reste vide ou affiche « refused to connect »

La console indique une violation de `frame-ancestors` : **l'origine de votre page n'est pas autorisée**.

- Vérifiez l'origine exacte de la page (`location.origin` dans la console) : schéma, sous-domaine et port.
- Ajoutez-la aux **origines autorisées** de l'application, sans chemin ni `/` final.
- Vérifiez que l'application est **active** et que **« Peut agir en tant qu'utilisateur »** est cochée : sinon, aucune origine n'est autorisée.
- Attendez une minute (cache) puis rechargez.

## « Composeur indisponible » : *The host page did not provide an embed token.*

L'iframe n'a pas reçu de jeton dans les 15 secondes.

- `getToken()` a échoué : regardez l'appel à votre endpoint dans l'onglet Réseau et le callback `onError`.
- L'`applicationId` passé à `mount()` ne correspond pas à l'application dont les origines incluent votre page.
- Intégration manuelle : le jeton est envoyé avec un `targetOrigin` qui n'est pas l'origine de Rocket Mailer, ou avant le message `ready`.

## « Composeur indisponible » : *Le jeton ne correspond pas à cette application.*

Le jeton a été émis avec le secret d'une **autre** application que celle indiquée dans `applicationId`. Vérifiez la configuration de votre backend : secret et identifiant doivent venir de la même application.

## Votre endpoint reçoit `401` de Rocket Mailer

| Message | Solution |
|---|---|
| `Invalid application token.` | Secret erroné ou régénéré, ou application désactivée. |
| `This application is not allowed to impersonate users.` | Cochez « Peut agir en tant qu'utilisateur ». |
| `Authentication failed.` | L'utilisateur n'existe pas ou est désactivé dans Rocket Mailer. Créez-le, ou lancez une synchronisation LDAP. |

## Votre endpoint reçoit `403`

L'en-tête `X-Impersonate-User` est absent. Sans lui, une application ne peut appeler que `GET /api/me`.

## L'envoi échoue après un long moment d'inactivité

Le jeton a expiré et n'a pas pu être renouvelé : `getToken()` échoue, souvent parce que la session de **votre** application a expiré. Gérez `onError` pour inviter l'utilisateur à se reconnecter.

## Une pièce jointe est refusée

| Message | Cause |
|---|---|
| `413` *The file is too large (maximum 10 MB).* | Le fichier dépasse `ATTACHMENT_MAX_SIZE`. |
| *Files of type ".exe" cannot be attached.* | Extension bloquée : exécutables et scripts. |
| *Attachments exceed 25 MB in total.* | La somme des pièces jointes dépasse `ATTACHMENTS_MAX_TOTAL_SIZE`. |
| *… has already been sent with another email.* | Une pièce jointe ne part qu'avec un seul email : envoyez à nouveau le fichier. |
| `403` *You can only attach files you uploaded.* | Votre backend a envoyé le fichier au nom d'un **autre** utilisateur que celui du composeur. |

## `setDraft()` n'a aucun effet

Il a été appelé avant que le composeur soit prêt. Appelez-le dans `onReady` ou après, ou passez le brouillon initial via l'option `draft`.

## La hauteur de l'iframe ne s'ajuste pas

`autoResize` est à `false`, ou une règle CSS de votre page impose une hauteur à l'iframe. Laissez la hauteur libre, ou gérez-la vous-même.

## Le script `embed.js` est bloqué

Votre propre `Content-Security-Policy` n'autorise pas Rocket Mailer. Ajoutez son origine à `script-src` et `frame-src` (voir [Sécurité](/embed/security#autoriser-rocket-mailer-dans-votre-propre-csp)).
