Le **composeur embarqué** affiche l'éditeur d'emails de Rocket Mailer dans une page de **votre** application (CRM, ERP, portail…). L'utilisateur compose et envoie sans changer d'outil. L'email part **en son nom**, avec l'import de templates et l'historique dans Rocket Mailer.

## Ce qu'il vous faut

::steps{level="3"}

### Une application déclarée dans Rocket Mailer

Un administrateur crée l'application. Il obtient un **jeton secret** (`rma_…`), autorise l'**impersonation** et déclare les **origines** des pages qui afficheront le composeur.

[Déclarer l'application →](/embed/application)

### Un endpoint sur votre serveur

Il identifie l'utilisateur connecté à **votre** application et demande pour lui un **jeton d'embed** de courte durée à Rocket Mailer, avec le secret de l'application. Le secret ne quitte jamais votre serveur.

[Écrire l'endpoint de jeton →](/embed/token-endpoint)

### Trois lignes dans votre page

Le script `embed.js` crée l'iframe, lui transmet le jeton, la redimensionne et vous remonte les événements.

[Intégrer le widget →](/embed/widget)

::

## Comment ça marche

::embed-flow
::

1. **L'iframe ne reçoit jamais le secret.** Elle reçoit un jeton d'embed (JWT) valable **15 minutes**, lié à **un utilisateur** et à **une application**. Ce jeton ne donne accès qu'à la composition et à l'envoi.
2. **Le jeton passe par `postMessage`, pas par l'URL.** Il n'apparaît donc ni dans les logs, ni dans l'historique, ni dans les en-têtes `Referer`. L'iframe n'accepte un jeton que de la page parente, et seulement si celle-ci est sur une origine autorisée.
3. **L'iframe n'est affichable que sur vos origines.** Rocket Mailer envoie `Content-Security-Policy: frame-ancestors <vos origines>` : ailleurs, le navigateur refuse de l'afficher.
4. **Le jeton est renouvelé automatiquement.** Quand il expire, l'iframe en redemande un et `embed.js` rappelle votre `getToken()`, sans que l'utilisateur perde son brouillon.

## Ce que voit l'utilisateur

Le composeur complet : destinataires (À, Cc, Cci), objet, import de templates et éditeur riche. Un bandeau indique « Envoi en tant que *Nom* · via *Votre application* ». Après l'envoi, votre page reçoit l'événement `onSent`. L'email apparaît aussi dans l'historique de l'utilisateur dans Rocket Mailer, avec le nom de votre application.

::note
L'utilisateur doit exister et être actif dans Rocket Mailer : compte local, ou compte synchronisé depuis l'annuaire LDAP. L'application agit **en son nom**, mais **jamais** avec le rôle administrateur, même si l'utilisateur est administrateur.
::

## En bref

::code-group
```ts [serveur.ts]
// 1. Votre backend : jeton d'embed pour l'utilisateur connecté
app.post('/rocket-mailer/token', requireLogin, async (req, res) => {
  const r = await fetch(`${ROCKET_MAILER_API}/api/embed/token`, {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${process.env.ROCKET_MAILER_APP_TOKEN}`,
      'X-Impersonate-User': req.user.email,
    },
  })
  res.status(r.status).json(await r.json())
})
```

```html [page.html]
<!-- 2. Votre page -->
<script src="https://mailer.exemple.com/embed.js"></script>
<div id="mailer"></div>
<script>
  RocketMailer.mount('#mailer', {
    baseUrl: 'https://mailer.exemple.com',
    applicationId: '0199a1b2-…',
    getToken: () => fetch('/rocket-mailer/token', { method: 'POST' })
      .then(r => r.json()).then(d => d.token),
    onSent: (email) => console.log('Envoyé :', email.subject),
  })
</script>
```
