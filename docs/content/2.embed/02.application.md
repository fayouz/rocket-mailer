Chaque application qui embarque le composeur ou appelle l'API est déclarée par un **administrateur** Rocket Mailer.

## Depuis l'interface

::steps{level="3"}

### Ouvrir « Applications »

Dans Rocket Mailer, menu **Applications**, puis **Nouvelle application**.

### Renseigner l'application

| Champ | Valeur |
|---|---|
| **Nom** | Affiché à l'utilisateur (« via *Nom* ») et dans l'historique des envois. |
| **Description** | Libre. |
| **Peut agir en tant qu'utilisateur** | **Obligatoire pour le composeur embarqué.** Autorise l'en-tête `X-Impersonate-User` et la création de jetons d'embed. |
| **Origines autorisées** | Les origines des pages qui afficheront le composeur, ex. `https://crm.exemple.com`. |
| **Expéditeur de l'application** | **Obligatoire pour envoyer.** Nom et adresse « De » par défaut de ses envois, ex. `Mon CRM <contact@crm.exemple.com>`. L'adresse par défaut de Rocket Mailer est proposée en suggestion. |
| **Adresses d'expédition qu'elle peut imposer** | Optionnel. Adresses ou domaines que l'application peut utiliser comme « De », ex. `*@crm.exemple.com`. |

### Copier le jeton secret

Rocket Mailer affiche le jeton **une seule fois**, avec un exemple d'intégration pré-rempli. Stockez-le dans la configuration **serveur** de votre application, par exemple dans une variable d'environnement ou un coffre de secrets.

### Noter l'identifiant de l'application

Le widget a besoin de l'**identifiant** de l'application (UUID), visible dans l'exemple d'intégration et dans la réponse de l'API. L'identifiant n'est pas secret.

::

::warning
Le jeton `rma_…` donne accès à l'API au nom de **n'importe quel** utilisateur de Rocket Mailer. Il ne doit **jamais** apparaître dans du code exécuté par le navigateur, dans un dépôt Git ou dans des logs. Rocket Mailer n'en stocke qu'une empreinte (SHA-256) : un jeton perdu ne peut pas être réaffiché, seulement régénéré.
::

## Origines autorisées

Une origine, c'est **schéma + hôte + port**, sans chemin ni `/` final :

| Correct | Incorrect |
|---|---|
| `https://crm.exemple.com` | `https://crm.exemple.com/` (slash final) |
| `https://crm.exemple.com:8443` | `https://crm.exemple.com/clients` (chemin) |
| `http://localhost:4000` | `crm.exemple.com` (sans schéma) |

La correspondance est **exacte** : `https://exemple.com` n'autorise pas `https://www.exemple.com`, et `http://` n'autorise pas `https://`. Déclarez chaque origine qui affichera le composeur, y compris vos environnements de recette.

::note
Les origines sont mises en cache jusqu'à **une minute**. Après une modification, rechargez la page qui embarque le composeur au bout de quelques instants.
::

## Adresses d'expédition

Une application n'envoie **jamais** depuis les adresses de Rocket Mailer (les [Réglages](/administration/settings), l'adresse par défaut de la plateforme) ni depuis l'adresse personnelle de l'utilisateur. Son composeur ne propose que ce qu'elle a configuré :

- son **expéditeur**, la valeur par défaut ;
- ses [boîtes d'envoi](/administration/mailboxes).

Sans expéditeur ni boîte d'envoi, le composeur affiche « Aucune adresse d'expédition » et l'API refuse l'envoi (`422`).

Votre application peut aussi **imposer à la volée** une autre adresse, par exemple celle de l'agence ou du service de la fiche ouverte :

- dans le composeur embarqué : `setDraft({ from: 'Agence Lyon <lyon@crm.exemple.com>' })` ;
- par l'API : le champ `from` de `POST /api/emails`.

Cette adresse doit être couverte par les **adresses d'expédition** déclarées sur l'application :

| Motif | Autorise |
|---|---|
| `lyon@crm.exemple.com` | exactement cette adresse |
| `*@crm.exemple.com` | toutes les adresses du domaine `crm.exemple.com` (pas ses sous-domaines) |

Les réponses reviennent à l'utilisateur (`Reply-To`). Vérifiez que votre relais SMTP est autorisé à émettre pour ces domaines (SPF, DKIM) : sinon, les emails risquent d'être classés en spam.

## Cycle de vie

| Action | Effet |
|---|---|
| **Désactiver** l'application | Tous les appels avec son jeton sont refusés, **et les composeurs embarqués ouverts cessent de fonctionner** dès leur prochaine requête. |
| **Régénérer le jeton** | L'ancien jeton `rma_…` est refusé immédiatement. Les jetons d'embed déjà émis restent valables jusqu'à leur expiration (15 minutes maximum). |
| **Retirer l'impersonation** | Plus de nouveaux jetons d'embed, et les composeurs ouverts sont coupés. |
| **Supprimer** | Comme une désactivation définitive. Les emails déjà envoyés restent dans l'historique, sans le nom de l'application. |

## Par l'API

Un administrateur peut aussi créer l'application avec son propre JWT :

```bash [Terminal]
curl -X POST https://mailer.exemple.com/api/applications \
  -H "Authorization: Bearer <jwt administrateur>" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "CRM",
    "canImpersonate": true,
    "allowedOrigins": ["https://crm.exemple.com"]
  }'
```

```json [Réponse 201]
{
  "id": "0199a1b2-7c3e-7d41-9f0a-4b2c6d8e1f23",
  "name": "CRM",
  "tokenHint": "rma_5f2c1a",
  "plainToken": "rma_5f2c1a…",
  "canImpersonate": true,
  "allowedOrigins": ["https://crm.exemple.com"],
  "enabled": true
}
```

`plainToken` n'est présent **que** dans cette réponse. Pour le renouveler : `POST /api/applications/{id}/regenerate-token`.
