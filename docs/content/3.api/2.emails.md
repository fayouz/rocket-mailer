## Envoyer un email

```bash [Terminal]
curl -X POST https://mailer.exemple.com/api/emails \
  -H "Authorization: Bearer rma_…" \
  -H "X-Impersonate-User: alice@exemple.com" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "from": "Agence Lyon <lyon@crm.exemple.com>",
    "to": ["client@exemple.com"],
    "cc": [],
    "bcc": [],
    "subject": "Votre devis",
    "htmlBody": "<p>Bonjour,</p><p>Voici votre devis.</p>",
    "template": "/api/email_templates/0199…",
    "attachments": ["/api/attachments/0199…"]
  }'
```

::field-group
  :::field{name="from" type="string"}
  Adresse d'expédition, `"Nom <email>"` ou `"email"`. Si elle est absente, l'adresse par défaut des Réglages est utilisée. Voir [Adresse d'expédition](#adresse-dexpédition).
  :::

  :::field{name="to" type="string[]" required}
  1 à 50 adresses valides.
  :::

  :::field{name="cc" type="string[]"}
  50 adresses maximum.
  :::

  :::field{name="bcc" type="string[]"}
  50 adresses maximum.
  :::

  :::field{name="subject" type="string" required}
  255 caractères maximum.
  :::

  :::field{name="htmlBody" type="string" required}
  Contenu HTML du message.
  :::

  :::field{name="template" type="string"}
  IRI d'un template utilisé (le vôtre ou un template partagé), pour la traçabilité.
  :::

  :::field{name="attachments" type="string[]"}
  IRI de pièces jointes déjà téléversées par le même utilisateur (10 au maximum, voir ci-dessous).
  :::
::

La réponse `202 Accepted` renvoie l'email avec le statut `queued`. Le worker l'envoie ensuite et le passe en `sent`, ou en `failed` avec `errorMessage`.

## Adresse d'expédition

`from` n'accepte que :

1. une des **adresses d'expédition** des [Réglages](/administration/settings) ;
2. l'**adresse de l'utilisateur**, sauf si les Réglages l'interdisent ;
3. pour un appel fait par une **application**, une adresse couverte par ses **adresses d'expédition autorisées** (`contact@exemple.com` ou tout un domaine `*@crm.exemple.com`).

Toute autre adresse est refusée (`422`). Quand l'email part d'une autre adresse que celle de l'utilisateur, les réponses lui reviennent grâce au `Reply-To`.

`GET /api/senders` liste les adresses proposées à l'utilisateur courant, la valeur par défaut en premier :

```json
[
  { "from": "Rocket Mailer <no-reply@exemple.com>", "email": "no-reply@exemple.com", "name": "Rocket Mailer", "default": true, "source": "settings" },
  { "from": "Alice Durand <alice@exemple.com>", "email": "alice@exemple.com", "name": "Alice Durand", "default": false, "source": "personal" }
]
```

Une erreur de validation renvoie `422` avec la liste des champs en erreur (`violations`).

## Pièces jointes

Une pièce jointe est d'abord **téléversée**, puis référencée dans l'email à l'envoi.

```bash [Terminal]
curl -X POST https://mailer.exemple.com/api/attachments \
  -H "Authorization: Bearer rma_…" \
  -H "X-Impersonate-User: alice@exemple.com" \
  -H "Accept: application/json" \
  -F "file=@devis-42.pdf"
```

```json [201 Created]
{ "id": "0199…", "filename": "devis-42.pdf", "mimeType": "application/pdf", "size": 48213 }
```

| Méthode | Endpoint | Rôle |
|---|---|---|
| `POST` | `/api/attachments` | Téléverser un fichier (multipart, champ `file`) |
| `GET` | `/api/attachments/{id}` | Métadonnées (propriétaire ou administrateur) |
| `GET` | `/api/attachments/{id}/download` | Télécharger le fichier (propriétaire ou administrateur) |
| `DELETE` | `/api/attachments/{id}` | Retirer une pièce jointe pas encore envoyée |

Règles :

- **Taille** : 10 Mo par fichier (`ATTACHMENT_MAX_SIZE`, sinon `413`) et 25 Mo par email (`ATTACHMENTS_MAX_TOTAL_SIZE`, sinon `422`).
- **Types refusés** : exécutables et scripts (`.exe`, `.bat`, `.cmd`, `.msi`, `.js`, `.vbs`, `.ps1`, `.jar`, `.lnk`, `.iso`…).
- **Propriété** : seules les pièces jointes téléversées par l'utilisateur qui envoie peuvent être jointes (sinon `403`).
- **Usage unique** : une pièce jointe ne part qu'avec un seul email (sinon `422`). Ensuite, elle ne peut plus être supprimée.
- **Nom de fichier** : il est conservé pour les destinataires, sans chemin ni caractères de contrôle.
- **Purge** : les fichiers jamais envoyés sont supprimés par `app:attachments:purge`.

## Consulter les envois

| Méthode | Endpoint | Accès |
|---|---|---|
| `GET` | `/api/emails` | Vos envois (tous pour un administrateur), du plus récent au plus ancien |
| `GET` | `/api/emails/{id}` | Détail, avec l'expéditeur (`from`), le contenu, les copies, les pièces jointes (`attachments`) et l'erreur éventuelle |

## Templates

| Méthode | Endpoint | Accès |
|---|---|---|
| `GET` | `/api/email_templates` | Vos templates et les templates partagés |
| `GET` | `/api/email_templates/{id}` | Détail : `html` (CSS inliné) et `projectData` (GrapesJS) |
| `POST` | `/api/email_templates` | Créer (vous en êtes le propriétaire) |
| `PATCH` | `/api/email_templates/{id}` | Propriétaire ou administrateur |
| `DELETE` | `/api/email_templates/{id}` | Propriétaire ou administrateur |
| `GET` | `/api/email_templates/{id}/versions` | Historique des versions |
| `POST` | `/api/email_templates/{id}/versions/{n}/restore` | Restaurer la version `n` |

Pour envoyer un template par l'API, récupérez son `html`, remplacez-y vos variables si besoin, puis passez-le en `htmlBody`.
