Une application peut travailler dans les [boîtes partagées](/administration/shared-inboxes) : retrouver les échanges d'un client, les lire et lui répondre depuis la boîte, dans le fil. Par exemple, un PMS affiche sur la fiche d'une réservation les messages du voyageur et y répond.

## Qui a accès

| Appel | Boîtes accessibles |
|---|---|
| L'application **pour elle-même** : son jeton `rma_…`, ou en mode suite un jeton d'accès Rocket Auth *client credentials* (audience `rocket-mailer`) de l'application liée | Les boîtes partagées **rattachées à l'application** (Administration → Boîtes d'envoi → Applications), réception activée |
| L'application **au nom d'un utilisateur** (`X-Impersonate-User`, application autorisée à l'emprunt d'identité) | Les boîtes dont l'utilisateur est **membre** |
| Composeur embarqué | Aucune |

Seuls ces endpoints sont ouverts aux applications ; assigner, fermer, les notes internes, la relève, les pièces jointes reçues et la gestion des membres restent réservés aux membres dans Rocket Mailer (`403`).

| Méthode | Chemin | Rôle |
|---|---|---|
| `GET` | `/api/inbox/mailboxes` | Boîtes accessibles (`role` : `application` pour l'application elle-même, sinon celui du membre) |
| `GET` | `/api/inbox/mailboxes/{id}/conversations` | Conversations, de la plus récente à la plus ancienne (100 au maximum) |
| `GET` | `/api/inbox/conversations/{id}` | Le fil : messages reçus (`inbound`), réponses (`reply`), notes (`note`) |
| `POST` | `/api/inbox/conversations/{id}/reply` | Répondre depuis la boîte, dans le fil |

Lire une conversation par l'API ne la marque pas comme lue pour les membres.

## Retrouver les conversations

| Paramètre | Exemple | Effet |
|---|---|---|
| `participant` | `participant=voyageur@exemple.com` | Conversations où cette adresse a écrit ou a été destinataire d'un email ouvrant la conversation (égalité exacte, sans tenir compte de la casse) |
| `externalRef` | `externalRef=booking-42` | Conversations portant cette référence (égalité exacte) |
| `status` | `status=open` | `open` ou `closed` |
| `q` | `q=parking` | Recherche dans l'objet, l'expéditeur et le texte |
| `mine` | `mine=1` | Assignées à l'utilisateur (au nom d'un utilisateur seulement) |

```bash [Terminal]
curl "https://mailer.exemple.com/api/inbox/mailboxes/0199…/conversations?participant=voyageur@exemple.com" \
  -H "Authorization: Bearer rma_…" -H "Accept: application/json"
```

Chaque conversation renvoie `id`, `subject`, `status`, `assignee`, `participants`, `lastFrom`, `snippet`, `messageCount`, `lastMessageAt`, `lastActivityAt`, `externalRef` et `unread` (toujours `false` pour l'application elle-même).

## Répondre

```bash [Terminal]
curl -X POST https://mailer.exemple.com/api/inbox/conversations/0199…/reply \
  -H "Authorization: Bearer rma_…" \
  -H "Idempotency-Key: booking-42-reply-1" \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{ "htmlBody": "<p>Bonjour, le code du portail est envoyé la veille.</p>", "externalRef": "booking-42" }'
```

::field-group
  :::field{name="htmlBody" type="string" required}
  Contenu HTML de la réponse.
  :::

  :::field{name="to" type="string[]"}
  Destinataires ; par défaut, le `Reply-To` (ou l'expéditeur) du dernier message reçu.
  :::

  :::field{name="cc" type="string[]"}
  Copies.
  :::

  :::field{name="externalRef" type="string"}
  Référence de votre application (190 caractères maximum), enregistrée sur la réponse **et sur la conversation** : la conversation se retrouve ensuite avec `?externalRef=`. Sans elle, la réponse reprend celle de la conversation.
  :::
::

La réponse `202 Accepted` renvoie l'élément `reply` : `id`, `author` (`null` pour l'application elle-même, sinon l'utilisateur), `application`, `to`, `cc`, `subject`, `status`, `externalRef`. La réponse part par le SMTP de la boîte, avec `In-Reply-To` et `References`, et sa copie va dans « Envoyés ».

L'en-tête `Idempotency-Key` évite d'envoyer deux fois la même réponse lors d'un nouvel essai : voir [Rejouer sans envoyer deux fois](/api/emails#rejouer-sans-envoyer-deux-fois-idempotency-key).

## Écrire le premier

Pour démarrer un échange (confirmation de réservation, par exemple), envoyez un email depuis la boîte partagée avec `POST /api/emails`, `mailbox` et `externalRef` (au nom d'un utilisateur, voir [Emails](/api/emails#envoyer-un-email)) : il ouvre une conversation fermée qui porte la référence, et la réponse du destinataire s'y range et la rouvre.
