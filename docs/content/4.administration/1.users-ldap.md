## Comptes locaux

Un administrateur les crée depuis la page **Utilisateurs** (mot de passe de 12 caractères minimum), ou en ligne de commande :

```bash [Terminal]
php bin/console app:user:create jean@exemple.com 'un-mot-de-passe-long' [--admin]
```

## Annuaire LDAP

### Configuration

| Variable | Exemple |
|---|---|
| `LDAP_ENABLED` | `1` |
| `LDAP_URL` | `ldaps://ldap.exemple.com:636` |
| `LDAP_BASE_DN` | `ou=people,dc=exemple,dc=com` |
| `LDAP_SEARCH_DN` / `LDAP_SEARCH_PASSWORD` | Compte de service en lecture |
| `LDAP_USER_FILTER` | `(objectClass=inetOrgPerson)` |
| `LDAP_ADMIN_GROUP_DN` | `cn=mailer-admins,ou=groups,dc=exemple,dc=com` (optionnel) |

Les attributs lus sont `mail` (obligatoire), `givenName`, `sn` et `memberOf`.

### Synchronisation

```bash [Terminal]
php bin/console app:ldap:sync            # à planifier (cron)
php bin/console app:ldap:sync --dry-run  # simulation, rien n'est écrit
```

Ou depuis la page **Utilisateurs**, avec les boutons **Simuler la synchro** et **Synchroniser LDAP**.

- Les entrées de l'annuaire sont **créées ou mises à jour** (email, prénom, nom).
- Les comptes LDAP qui ont disparu de l'annuaire sont **désactivés**, pas supprimés : leurs envois restent dans l'historique.
- Un compte **local** avec le même email n'est **jamais** repris par l'annuaire. Il est signalé comme conflit.
- Si `LDAP_ADMIN_GROUP_DN` est défini, le rôle administrateur suit l'appartenance au groupe (`memberOf`). Sinon, il se gère dans l'application.

### Connexion

Un compte LDAP se connecte avec son mot de passe d'annuaire, vérifié par un *bind* sur son DN. Rocket Mailer ne stocke pas ce mot de passe. Un mot de passe vide est toujours refusé : sur la plupart des serveurs, il donnerait un bind anonyme réussi.

::tip
Pour le composeur embarqué, les utilisateurs de votre application doivent exister dans Rocket Mailer. Si les deux partagent le même annuaire, planifiez la synchronisation pour que les nouveaux arrivants soient disponibles rapidement.
::
