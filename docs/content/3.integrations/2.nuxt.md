Le layer fournit le composant `<RocketMailerComposer>`, l'endpoint de jeton (serveur Nitro) et un utilitaire d'envoi côté serveur. Le secret reste dans la configuration serveur de Nuxt.

::steps{level="3"}

### Ajouter le layer

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['github:fayouz/rocket-mailer-nuxt'],
})
```

Le layer est téléchargé au démarrage de Nuxt. Pour un dépôt privé, définissez `GIGET_AUTH` (un jeton GitHub en lecture) dans l'environnement de build.

### Configurer

```bash [.env]
NUXT_PUBLIC_ROCKET_MAILER_URL=https://mailer.exemple.com
NUXT_PUBLIC_ROCKET_MAILER_APPLICATION_ID=0199a1b2-7c3e-7d41-9f0a-4b2c6d8e1f23
NUXT_ROCKET_MAILER_APP_TOKEN=rma_…
# Optionnel : URL interne (réseau Docker, Kubernetes…) pour les appels serveur
NUXT_ROCKET_MAILER_API_URL=http://rocket-mailer-front:3000
```

`NUXT_ROCKET_MAILER_APP_TOKEN` n'est lu que par le serveur Nitro. Il n'apparaît jamais dans le bundle client.

### Dire qui est connecté

Le layer demande l'email de l'utilisateur connecté à un hook Nitro. Branchez-y votre authentification :

::code-group
```ts [nuxt-auth-utils]
// server/plugins/rocket-mailer.ts
export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('rocket-mailer:user', async (event, context) => {
    const { user } = await requireUserSession(event)
    context.email = user.email
  })
})
```

```ts [@sidebase/nuxt-auth]
// server/plugins/rocket-mailer.ts
import { getServerSession } from '#auth'

export default defineNitroPlugin((nitro) => {
  nitro.hooks.hook('rocket-mailer:user', async (event, context) => {
    const session = await getServerSession(event)
    context.email = session?.user?.email ?? undefined
  })
})
```
::

Sans email, l'endpoint répond `401` : personne n'obtient de jeton sans être connecté à **votre** application.

### Afficher le composeur

```vue [pages/clients/[id].vue]
<script setup lang="ts">
const client = await useFetch(`/api/clients/${useRoute().params.id}`).data

const draft = computed(() => ({
  to: [client.value.email],
  template: '0199…',                                            // « Relance devis »
  variables: { client: { prenom: client.value.firstName }, devis: { numero: client.value.lastQuote } },
}))
</script>

<template>
  <RocketMailerComposer :draft="draft" @sent="email => refreshNuxtData()" />
</template>
```

::

## Référence du composant

| Prop | Type | Rôle |
|---|---|---|
| `draft` | `RocketMailerDraft` | Brouillon, **réactif** : chaque changement est transmis au composeur ([champs](/embed/prefill-events#champs-du-brouillon)) |
| `token-url` | `string` | Endpoint de jeton. Par défaut : `/api/rocket-mailer/token`, fourni par le layer |
| `get-token` | `() => Promise<string>` | À la place de `token-url`, quand l'endpoint demande plus que les cookies (voir [Nuxt + API Platform](/integrations/nuxt-api-platform)) |
| `min-height` | `number` | Hauteur minimale |
| `auto-resize` | `boolean` | `false` pour une hauteur fixe |

| Événement | Charge |
|---|---|
| `ready` | — |
| `sent` | L'email envoyé : `id`, `subject`, `to`, `status` |
| `error` | `Error` |

Méthode exposée (via une `ref`) : `setDraft(draft)`.

## Envoyer sans composeur

Pour les envois automatiques, par exemple une relance planifiée ou une confirmation de commande :

```ts [server/api/quotes/[id]/remind.post.ts]
export default defineEventHandler(async (event) => {
  const user = await resolveRocketMailerUser(event)
  if (!user) throw createError({ statusCode: 401 })

  return sendRocketMailerEmail(user, {
    to: ['claire@client.example'],
    template: '0199…',
    variables: { client: { prenom: 'Claire' }, devis: { numero: '42', montant: '1 250 €' } },
    attachments: [],   // ids de pièces jointes téléversées au nom de l'utilisateur
  })
})
```

| Utilitaire serveur | Rôle |
|---|---|
| `resolveRocketMailerUser(event)` | Email de l'utilisateur connecté (via votre hook) |
| `sendRocketMailerEmail(asUser, email)` | `POST /api/emails` au nom de `asUser`. `template` et `attachments` acceptent des ids |
| `rocketMailerFetch(path, { method, body, actAs })` | Tout autre appel à l'[API](/api/authentication), avec le secret |

Une variable de template manquante, une adresse d'expédition refusée… : l'appel échoue avec l'erreur de l'API (`422`).
