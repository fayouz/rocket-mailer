Quelle que soit la stack, une intégration a toujours les mêmes deux morceaux :

1. **côté serveur**, un endpoint qui obtient un jeton d'embed pour l'utilisateur connecté, avec le secret `rma_…` de l'application ;
2. **côté navigateur**, le composeur, qui appelle cet endpoint.

Rocket Mailer fournit des clients prêts à l'emploi pour ne pas réécrire ces morceaux dans chaque application :

| Votre application | Serveur (jeton, envois) | Navigateur (composeur) | Guide |
|---|---|---|---|
| **Nuxt** (Nitro fait le backend) | layer `@rocket-mailer/nuxt` | `<RocketMailerComposer>` du layer | [Application Nuxt](/integrations/nuxt) |
| **Nuxt + Symfony / API Platform** | bundle `rocket-mailer/rocket-mailer-bundle` | `<RocketMailerComposer>` du layer | [Nuxt + API Platform](/integrations/nuxt-api-platform) |
| **Symfony avec Twig** | bundle | `{{ rocket_mailer_composer() }}` | [Application Symfony](/integrations/symfony) |
| **Autre** (Laravel, Rails, Django, Express, Next…) | votre endpoint, en quelques lignes | web component `<rocket-mailer-composer>` | [Autre stack](/integrations/other) |

::tip
Dans Rocket Mailer, le bouton **Intégrer** du composeur (et **Code d'intégration** dans la page Applications) génère le code de chaque cas pour une application donnée, pré-rempli avec le brouillon en cours.
::

## Avant de commencer

Quel que soit le cas, un administrateur Rocket Mailer [déclare l'application](/embed/application) :

- **Peut agir en tant qu'utilisateur** activé ;
- l'**origine** de l'application appelante dans les origines autorisées, par exemple `https://crm.exemple.com` ;
- le **jeton secret** `rma_…` copié dans la configuration **serveur** de l'application appelante.

Les utilisateurs de l'application appelante doivent exister dans Rocket Mailer avec le même email : comptes locaux, ou synchronisés depuis le même annuaire LDAP.

## Où sont les clients ?

Ils sont développés dans le dépôt Rocket Mailer (`integrations/`), testés en CI avec chaque version de l'API, et publiés dans des dépôts miroirs :

| Client | Dépôt miroir | Installation |
|---|---|---|
| Layer Nuxt | `fayouz/rocket-mailer-nuxt` | `extends: ['github:fayouz/rocket-mailer-nuxt']` |
| Bundle Symfony | `fayouz/rocket-mailer-symfony` | `composer require rocket-mailer/rocket-mailer-bundle` (dépôt `vcs`) |

::note
Tant que les dépôts miroirs ne sont pas créés, installez directement depuis le monorepo :

- Nuxt : `extends: ['github:fayouz/rocket-mailer/integrations/nuxt#develop']` ;
- Symfony : un dépôt Composer de type `path` qui pointe vers une copie de `integrations/symfony`.
::
