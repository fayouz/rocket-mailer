Dans une application découpée en un front Nuxt et une API Symfony / API Platform, c'est **le backend qui connaît l'utilisateur**. Il garde donc le secret Rocket Mailer et fournit les jetons. Le front ne fait qu'afficher le composeur.

| Côté | Brique | Rôle |
|---|---|---|
| API Symfony | bundle `rocket-mailer/rocket-mailer-bundle` | `POST /api/rocket-mailer/token` derrière votre firewall, envois serveur |
| Front Nuxt | layer `@rocket-mailer/nuxt` | `<RocketMailerComposer>` qui appelle l'API pour ses jetons |

::steps{level="3"}

### Installer le bundle dans l'API

```bash [Terminal]
composer config repositories.rocket-mailer vcs https://github.com/fayouz/rocket-mailer-symfony
composer require rocket-mailer/rocket-mailer-bundle:dev-main
```

```php [config/bundles.php]
RocketMailer\Bundle\RocketMailerBundle::class => ['all' => true],
```

```yaml [config/packages/rocket_mailer.yaml]
rocket_mailer:
    url: '%env(ROCKET_MAILER_URL)%'
    app_token: '%env(ROCKET_MAILER_APP_TOKEN)%'
    application_id: '%env(ROCKET_MAILER_APPLICATION_ID)%'
```

### Exposer l'endpoint derrière le firewall de l'API

```yaml [config/routes/rocket_mailer.yaml]
rocket_mailer:
    resource: '@RocketMailerBundle/config/routes.php'
    prefix: /api        # → POST /api/rocket-mailer/token, protégé comme le reste de l'API
```

L'endpoint agit en tant que l'utilisateur authentifié par votre firewall (JWT, session…). Il prend `getEmail()` de votre classe User, sinon son identifiant s'il s'agit d'un email. Si vos utilisateurs sont identifiés autrement, remplacez le résolveur :

```php [src/RocketMailer/UserEmailResolver.php]
use RocketMailer\Bundle\Security\UserEmailResolverInterface;
use Symfony\Bundle\SecurityBundle\Security;
use Symfony\Component\DependencyInjection\Attribute\AsAlias;

#[AsAlias(UserEmailResolverInterface::class)]
final class UserEmailResolver implements UserEmailResolverInterface
{
    public function __construct(private readonly Security $security) {}

    public function currentUserEmail(): ?string
    {
        return $this->security->getUser()?->getProfessionalEmail();
    }
}
```

### Ajouter le layer au front

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['github:fayouz/rocket-mailer-nuxt'],
})
```

```bash [.env (front)]
NUXT_PUBLIC_ROCKET_MAILER_URL=https://mailer.exemple.com
NUXT_PUBLIC_ROCKET_MAILER_APPLICATION_ID=0199a1b2-…
# Pas de NUXT_ROCKET_MAILER_APP_TOKEN ici : le secret est dans l'API.
```

### Demander le jeton à l'API

Le composant doit appeler **votre API** avec **ses** identifiants :

::code-group
```vue [JWT (Authorization)]
<script setup lang="ts">
// Votre $fetch authentifié (ex. un plugin qui ajoute Authorization: Bearer <jwt>)
const { $api } = useNuxtApp()
const getToken = () => $api<{ token: string }>('/api/rocket-mailer/token', { method: 'POST' }).then(r => r.token)
</script>

<template>
  <RocketMailerComposer :get-token="getToken" :draft="{ to: [client.email] }" />
</template>
```

```vue [Cookie de session, même domaine]
<template>
  <!-- L'API est servie sur le même domaine que le front (ou proxifiée) : les cookies suffisent. -->
  <RocketMailerComposer token-url="/api/rocket-mailer/token" :draft="{ to: [client.email] }" />
</template>
```
::

::

::warning
N'utilisez pas l'endpoint Nitro du layer dans ce cas de figure : le front n'a ni le secret ni la connaissance de l'utilisateur. Laissez `NUXT_ROCKET_MAILER_APP_TOKEN` vide. L'endpoint Nitro répond alors `500`, et seul celui de l'API sert.
::

## Envois côté API

Dans vos state processors, contrôleurs ou handlers Messenger, injectez le client :

```php [src/State/QuoteRemindProcessor.php]
use RocketMailer\Bundle\RocketMailerClient;

public function __construct(private readonly RocketMailerClient $mailer, private readonly Security $security) {}

public function process(mixed $quote, Operation $operation, array $uriVariables = [], array $context = []): mixed
{
    $me = $this->security->getUser()->getEmail();
    $this->mailer->sendEmail($me, [
        'to' => [$quote->getClient()->getEmail()],
        'template' => $this->mailer->findTemplate($me, 'Relance devis')['id'],
        'variables' => ['client' => ['prenom' => $quote->getClient()->getFirstName()], 'devis' => ['numero' => $quote->getNumber()]],
    ]);

    return $quote;
}
```

Voir [Application Symfony](/integrations/symfony#client) pour toutes les méthodes du client.
